# MPU-6050: การทำงาน ค่าที่วัด และการประยุกต์ใช้

Oct 14, 2026 · @J

## ภาพรวม MPU-6050 คืออะไร

MPU-6050 คือ **IMU (Inertial Measurement Unit)** รุ่นที่นิยมที่สุดในโลก Embedded Systems ผลิตโดย InvenSense (ปัจจุบันเป็นของ TDK) บรรจุ sensor 2 ตัวไว้ใน chip เดียว:

| Sensor | วัดอะไร | หน่วย |
| --- | --- | --- |
| 3-axis Accelerometer | ความเร่งเชิงเส้น (linear acceleration) | m/s² หรือ g |
| 3-axis Gyroscope | ความเร็วเชิงมุม (angular velocity) | °/s (degrees per second) |

นอกจากนี้ยังมี **Digital Motion Processor (DMP)** ในตัว — co-processor สำหรับคำนวณ sensor fusion บน chip โดยไม่ต้องให้ MCU ทำเอง

**สเปกที่สำคัญ:**

| พารามิเตอร์ | ค่า |
| --- | --- |
| แรงดันไฟฟ้า | 3.3V (logic) / 2.375–3.46V (core) |
| Interface | I2C (400 kHz fast mode) |
| I2C Address | 0x68 (AD0=GND) หรือ 0x69 (AD0=VCC) |
| ADC resolution | 16-bit per axis |
| Accelerometer range | ±2g / ±4g / ±8g / ±16g (เลือกได้) |
| Gyroscope range | ±250 / ±500 / ±1000 / ±2000 °/s |
| Sampling rate สูงสุด | 8 kHz (gyro), 1 kHz (accel) |

## หลักการทำงานของ Accelerometer

### วัดอะไร?

Accelerometer วัด **specific force** — ผลรวมของ gravity กับ linear acceleration จากการเคลื่อนที่จริง:

```
ค่าที่อ่านได้ = แรงโน้มถ่วง (g) + acceleration จากการเคลื่อนที่
```

สิ่งสำคัญที่ต้องเข้าใจ: **ถ้าวางนิ่งบนโต๊ะ จะยังอ่านค่าได้ \~9.8 m/s²** เพราะ chip รู้สึกถึง gravity ตลอดเวลา ไม่ใช่ 0 เหมือนที่คิด

### หน่วยและ Range

Adafruit MPU6050 library คืนค่าเป็น **m/s²** เสมอ (1g = 9.80665 m/s²)

Range ที่เลือกได้กำหนดว่า 16-bit ADC ครอบคลุมช่วงกว้างแค่ไหน:

| Range | Resolution (per bit) | ใช้เมื่อ |
| --- | --- | --- |
| ±2g | 0.061 mg/bit | วัด tilt, orientation ที่เคลื่อนที่ช้า |
| ±4g | 0.122 mg/bit | การเคลื่อนไหวทั่วไป เช่น gesture |
| ±8g | 0.244 mg/bit | การกระแทกเบา, robot arm |
| ±16g | 0.488 mg/bit | การกระแทกแรง, drone, RC car |

> โปรเจกต์นี้ใช้ **±4g** (`MPU6050_RANGE_4_G`) เหมาะกับการจับ gesture มือ ที่ไม่เกิน 4 เท่าของ gravity

### วิธีที่ chip วัดค่าจริงๆ

ภายใน chip มี **MEMS (Micro-Electro-Mechanical System)** — โครงสร้างจิ๋วระดับ micrometres ที่ทำจาก silicon:

```
[mass เล็กๆ ห้อยด้วย spring]
    ↓
เมื่อมีแรงกระทำ mass เคลื่อนที่
    ↓
ระยะห่างระหว่าง capacitor plate เปลี่ยน
    ↓
capacitance เปลี่ยน → voltage เปลี่ยน
    ↓
16-bit ADC แปลงเป็น digital
    ↓
ส่งออก I2C
```

กระบวนการนี้เกิดขึ้นพร้อมกันทั้ง 3 แกน (X, Y, Z) อิสระจากกัน

## หลักการทำงานของ Gyroscope

### วัดอะไร?

Gyroscope วัด **angular velocity** — ความเร็วในการหมุนรอบแกน หน่วยคือ **°/s (degrees per second)**

```
วางนิ่ง → 0 °/s ทุกแกน  (ไม่รู้สึก gravity)
หมุนรอบแกน Z 1 รอบ/วินาที → gyroZ = 360 °/s
```

ต่างจาก Accelerometer ตรงที่: **Gyroscope ไม่รู้สึกถึง gravity** — ถ้าวางนิ่งจะอ่านได้ 0 °/s เสมอ (มี noise เล็กน้อย)

### หลักการ Coriolis Effect

MEMS Gyroscope ทำงานโดยอาศัย **Coriolis force**:

```
1. mass ภายใน chip สั่นอยู่ตลอดเวลาในแนวแกนหนึ่ง (driven vibration)
2. เมื่อ chip หมุน → Coriolis force ดัน mass ในแนวตั้งฉาก
3. วัดการเคลื่อนที่ที่เกิดจาก Coriolis → แปลงเป็น angular velocity
```

### ความต่างหลักกับ Accelerometer

|  | Accelerometer | Gyroscope |
| --- | --- | --- |
| วัด | Linear acceleration + gravity | Angular velocity |
| หน่วย | m/s² หรือ g | °/s |
| ตอนวางนิ่ง | อ่านได้ \~9.8 m/s² (gravity) | อ่านได้ \~0 °/s |
| ปัญหาหลัก | noise จากการสั่นสะเทือน | drift สะสมเมื่อ integrate |
| ใช้คำนวณ | ตำแหน่ง tilt, แรงกระแทก | มุมการหมุน, orientation |

### Drift — ข้อจำกัดสำคัญของ Gyroscope

ถ้าต้องการรู้ **มุม** (angle) จะต้อง integrate angular velocity ตามเวลา:

```
angle(t) = ∫ ω dt
```

ปัญหาคือ Gyroscope มี **bias noise** เล็กน้อย เมื่อ integrate สะสมนานๆ จะกลายเป็น error ที่ใหญ่ขึ้นเรื่อยๆ เรียกว่า **gyroscope drift** — นี่คือเหตุผลหลักที่ต้องทำ **sensor fusion** รวม Gyroscope กับ Accelerometer

## Digital Motion Processor (DMP)

DMP คือ **co-processor ภายใน MPU-6050** ทำ sensor fusion และ motion processing บน chip โดยตรง แทนที่จะให้ MCU หลักทำ

**ทำอะไรได้บ้าง:**

| ความสามารถ | อธิบาย |
| --- | --- |
| Quaternion output | คำนวณ 3D orientation โดยไม่มี gimbal lock |
| Tap detection | ตรวจจับการเคาะ/กระแทก |
| Gesture recognition | จำแนก gesture เบื้องต้น |
| Step counting | นับก้าวเดิน (pedometer) |
| Free-fall detection | ตรวจจับการตกอิสระ |

**ข้อดี:** ลด CPU load บน MCU ลงมาก — ESP32 ไม่ต้องคำนวณ Kalman filter เอง

**ข้อจำกัด:** DMP firmware เป็น proprietary, library support ซับซ้อนกว่า raw mode — โปรเจกต์นี้ไม่ใช้ DMP เพราะ Edge Impulse จัดการ DSP pipeline เองอยู่แล้ว

## I2C Interface และการอ่านค่า

### การสื่อสาร I2C

MPU-6050 ใช้ I2C protocol — สาย 2 เส้น (SDA + SCL) สำหรับ sensor หลายตัวบน bus เดียวกัน:

```
ESP32-S3          MPU-6050
  GPIO8 (SDA) ←──────→ SDA
  GPIO9 (SCL) ──────→ SCL
  3V3         ──────→ VCC
  GND         ──────→ GND
              AD0 → GND = address 0x68
              AD0 → VCC = address 0x69
```

### Register Map — ค่าอยู่ที่ไหน

ทุกค่าของ MPU-6050 เก็บอยู่ใน register ภายใน chip Adafruit library อ่าน register เหล่านี้ให้อัตโนมัติ:

| Register | ชื่อ | เก็บอะไร |
| --- | --- | --- |
| 0x3B–0x3C | ACCEL\_XOUT | Accelerometer X (16-bit, 2 bytes) |
| 0x3D–0x3E | ACCEL\_YOUT | Accelerometer Y |
| 0x3F–0x40 | ACCEL\_ZOUT | Accelerometer Z |
| 0x43–0x44 | GYRO\_XOUT | Gyroscope X |
| 0x45–0x46 | GYRO\_YOUT | Gyroscope Y |
| 0x47–0x48 | GYRO\_ZOUT | Gyroscope Z |
| 0x41–0x42 | TEMP\_OUT | Temperature (°C) |

### การแปลงค่าจาก raw int16 → m/s²

ค่าดิบที่ ADC อ่านได้คือ signed 16-bit integer (−32768 ถึง +32767) Adafruit library แปลงให้ด้วยสูตร:

```
accel_m_s2 = raw_int16 / sensitivity_scale_factor

ที่ ±4g:  scale factor = 8192 LSB/g
ดังนั้น:  accel_m_s2 = (raw / 8192) × 9.80665

ตัวอย่าง: raw = 8192 → 1g → 9.81 m/s²
           raw = 32767 → ~4g → ~39.2 m/s²
```

## ค่าที่วัดได้จริงในสถานการณ์ต่างๆ

### Accelerometer (m/s²)

| สถานการณ์ | accX | accY | accZ | สังเกต |
| --- | --- | --- | --- | --- |
| วางนิ่ง แกน Z ชี้ขึ้น | \~0 | \~0 | **+9.81** | gravity เต็มบน Z |
| วางนิ่ง แกน X ชี้ขึ้น | **+9.81** | \~0 | \~0 | gravity ย้ายไป X |
| คว่ำลง (Z ชี้ลง) | \~0 | \~0 | **−9.81** | gravity กลับทิศ |
| เขย่าแนวนอน (X) | ±20–40 | \~0 | \~9.81 | Z ยังมี gravity |
| ท่า circle (วนมือ) | แกว่ง ±15 | แกว่ง ±15 | \~9.81 | X และ Y แกว่งพร้อมกัน |
| ท่า up\_down | \~0 | \~0 | 0–20 | Z เปลี่ยนแปลงหลัก |
| กระแทกโต๊ะ | spike ±50+ | spike ±50+ | spike | เกิน range ±4g ได้ |

### Gyroscope (°/s)

| สถานการณ์ | gyroX | gyroY | gyroZ | สังเกต |
| --- | --- | --- | --- | --- |
| วางนิ่ง | \~0 | \~0 | \~0 | เกือบ 0 มี noise ±0.5 |
| หมุนรอบ Z (yaw) | \~0 | \~0 | ±90–360 | ขึ้นกับความเร็วหมุน |
| พยักหน้า (pitch) | ±90–180 | \~0 | \~0 | หัวก้มเงย |
| ส่ายหัว (roll) | \~0 | ±90–180 | \~0 | หัวเอียง |
| ท่า circle เร็ว | ±100–500 | ±100–500 | ±50 | ทุกแกนเปลี่ยน |

### อธิบาย Axis Orientation

```
        Z ↑
        │
        │    Y
        │   ↗
        │  /
        │ /
        └──────→ X

เมื่อวาง chip แบน:
  X = แนวนอน (ซ้าย-ขวา)
  Y = แนวนอน (หน้า-หลัง)
  Z = แนวตั้ง (ขึ้น-ลง)
```

## การประยุกต์ใช้งาน

### 1. Gesture Recognition (โปรเจกต์นี้)

**ใช้ค่า:** Accelerometer X, Y, Z

จับรูปแบบการเคลื่อนไหวของมือหรือวัตถุ เช่น วงกลม, ขึ้น-ลง, ส่ายซ้ายขวา Pipeline คือ:

```
Raw accel signal → FFT → Spectral features → Neural Network → class label
```

นิยมใช้ใน: รีโมทคอนโทรล, smart glove, เกม, AR/VR controller

### 2. Drone / Quadcopter Flight Control

**ใช้ค่า:** Accelerometer + Gyroscope (ทั้ง 6 แกน)

Gyroscope อ่านค่า angular velocity → ระบบ PID controller ปรับ motor speed เพื่อให้ drone นิ่ง Accelerometer ช่วย compensate drift ของ gyroscope ผ่าน **Complementary Filter หรือ Kalman Filter**:

```
angle = α × (angle + gyro × dt) + (1−α) × accel_angle
โดยทั่วไป α = 0.98
```

### 3. Robotics — Robot Arm & Mobile Robot

**ใช้ค่า:** Accelerometer (tilt), Gyroscope (rotation rate)

- **Balancing robot** (self-balancing เหมือน Segway): ต้องรู้มุม tilt แม่นยำมากเพื่อควบคุม motor
- **Robot arm joint**: ติด IMU ที่ข้อต่อแต่ละข้อ อ่านมุมแต่ละ joint
- **Odometry**: ประมาณตำแหน่งจาก acceleration เมื่อไม่มี GPS

### 4. Fall Detection (ตรวจจับการล้ม)

**ใช้ค่า:** Accelerometer ทุกแกน

เมื่อคนล้ม จะเกิด spike ของ acceleration ตามด้วยค่าต่ำผิดปกติ (free-fall phase) แล้วตามด้วย impact spike:

```
ปกติ: |a| ≈ 9.8 m/s²
Free-fall: |a| < 3 m/s²  (ลอยอยู่กลางอากาศ)
Impact: |a| > 30 m/s²  (กระแทกพื้น)
```

ใช้ใน: smartwatch, อุปกรณ์ผู้สูงอายุ, หมวก safety

### 5. Activity Recognition & Pedometer

**ใช้ค่า:** Accelerometer ทุกแกน

ก้าวเดินสร้าง pattern ซ้ำๆ บน accelerometer — นับ peak ที่สม่ำเสมอ = นับก้าว ระบบที่ซับซ้อนขึ้นแยกได้ว่าเดิน วิ่ง ปั่นจักรยาน หรือขึ้นบันได

ใช้ใน: fitness tracker, smartwatch, โทรศัพท์

### 6. Vehicle & Industrial Monitoring

**ใช้ค่า:** Accelerometer (vibration), Gyroscope (orientation)

- **Vibration analysis**: ตรวจจับความผิดปกติของเครื่องจักร ถ้าความถี่การสั่นเปลี่ยน = bearing เสียหาย
- **Vehicle tilt monitoring**: รถบรรทุกที่เอียงเกิน threshold → เตือน
- **Dashcam G-sensor**: บันทึกข้อมูล acceleration ตอนชนเพื่อวิเคราะห์อุบัติเหตุ

### สรุป: ใช้ค่าไหนสำหรับงานไหน

| งาน | Accel | Gyro | Sensor Fusion |
| --- | --- | --- | --- |
| Gesture recognition | ✓ | อาจใช้ | ไม่จำเป็น |
| Drone stabilization | ✓ | ✓ | จำเป็น |
| Tilt / inclination | ✓ | — | ไม่จำเป็น |
| Rotation tracking | — | ✓ | แนะนำ |
| Fall detection | ✓ | — | ไม่จำเป็น |
| Activity recognition | ✓ | อาจใช้ | ไม่จำเป็น |
| Navigation (dead reckoning) | ✓ | ✓ | จำเป็นมาก |

## MPU-6050 ในโลกจริง — ใช้ในงานอะไรบ้าง

### ผลิตภัณฑ์ที่มี IMU อยู่ข้างใน

แทบทุก device ที่เคลื่อนไหวหรือต้องรู้ทิศทางในชีวิตประจำวันมี IMU อยู่ข้างใน:

| กลุ่มผลิตภัณฑ์ | ตัวอย่าง | ใช้ทำอะไร |
| --- | --- | --- |
| สมาร์ทโฟน | ทุกรุ่น | หมุนหน้าจอ, นับก้าว, ถ่ายภาพกันสั่น |
| Smartwatch / Fitness tracker | Apple Watch, Fitbit | นับก้าว, ตรวจจับการล้ม, sleep tracking |
| Drone / UAV | DJI, racing drone | Flight stabilization, return-to-home |
| VR/AR Headset | Meta Quest, HoloLens | ติดตามการหมุนหัว (head tracking) |
| Controller เกม | Nintendo Switch Joy-Con | Motion control |
| รถยนต์ | ทุกรุ่นที่มี stability control | ESP (Electronic Stability Program) |
| ของเล่นและ robot | LEGO SPIKE, robot แข่งขัน | Balance, navigation |
| อุปกรณ์การแพทย์ | exoskeleton, prosthetics | ตรวจจับเจตนาการเคลื่อนที่ |

### งานอุตสาหกรรมที่ใช้จริง

**Predictive Maintenance (การบำรุงรักษาเชิงพยากรณ์)**

ติด IMU/accelerometer บนมอเตอร์หรือเครื่องจักร อ่าน vibration pattern ตลอดเวลา เมื่อ pattern เปลี่ยนจาก baseline → แจ้งเตือนก่อนที่จะเสีย ไม่ต้องรอให้พัง:

```
มอเตอร์ปกติ:  vibration pattern A (FFT มี peak ที่ 50 Hz)
มอเตอร์ bearing เสีย: peak ใหม่ที่ 120 Hz ปรากฏขึ้น
→ เตือนก่อนเสียหาย 2-4 สัปดาห์
```

**Structural Health Monitoring**

ติด sensor บนสะพาน, อาคาร, หรือปีกเครื่องบิน วัด vibration และ deformation ต่อเนื่อง ตรวจจับความผิดปกติก่อนเกิดความเสียหาย

**Logistics & Cold Chain**

ติดกล่องสินค้าที่ขนส่ง ตรวจจับว่ามีการกระแทก (shock > threshold) ระหว่างทางไหม ใช้ใน: อุปกรณ์ทางการแพทย์, สินค้าแตกง่าย

## ตัวอย่าง: Predictive Maintenance → TinyML บน Edge Device

นี่คืองานที่เชื่อมต่อระหว่าง real-world application กับสิ่งที่เราเรียนในคอร์สนี้ได้ชัดที่สุด

### ปัญหาที่ต้องแก้

โรงงานมีมอเตอร์ 500 ตัว การส่งข้อมูล vibration ดิบ 98 Hz จากทุกตัวขึ้น cloud ตลอดเวลาคือ:

```
500 มอเตอร์ × 3 แกน × 98 Hz × 4 bytes × 60 วินาที = ~352 MB/นาที
→ bandwidth สูง, latency สูง, cloud cost สูง, ทำงานออฟไลน์ไม่ได้
```

### วิธีแก้ด้วย TinyML

แทนที่จะส่งข้อมูลดิบขึ้น cloud ให้รัน ML model บน microcontroller ข้างมอเตอร์เลย:

```
[MPU-6050 บนมอเตอร์]
        ↓  raw vibration 98 Hz
[ESP32-S3 + Edge Impulse model]
        ↓  inference ทุก 2 วินาที
        → "normal"       → ไม่ส่งอะไร
        → "bearing_wear" → ส่ง alert ขึ้น cloud
        → "imbalance"    → ส่ง alert ขึ้น cloud
```

ส่งขึ้น cloud เฉพาะ **event** ที่สำคัญ ไม่ใช่ raw data ทั้งหมด — bandwidth ลดลง 99%+

### ขั้นตอน (เหมือนกับที่เราทำในคอร์สนี้ทุกอย่าง)

1. **เก็บ dataset** — อัดเสียง vibration ของมอเตอร์ปกติ, มอเตอร์ bearing เริ่มสึก, มอเตอร์ imbalance บน Edge Impulse
2. **เทรนโมเดล** — Spectral Analysis + Classification เหมือนกัน
3. **Deploy** — Build Arduino library → flash ลง ESP32-S3 ข้างมอเตอร์
4. **Inference** — รันตลอด 24/7 ไม่ต้องใช้ internet ยกเว้นตอน alert

### เปรียบเทียบ: gesture recognition vs predictive maintenance

|  | Gesture (คอร์สนี้) | Predictive Maintenance |
| --- | --- | --- |
| Sensor | MPU-6050 accel | MPU-6050 accel (เหมือนกัน) |
| Signal | การเคลื่อนไหวมือ | vibration มอเตอร์ |
| Frequency | 98 Hz | 98–1000 Hz |
| Window | 2 วินาที | 1–5 วินาที |
| Class | circle, up\_down, side\_side | normal, bearing\_wear, imbalance |
| Pipeline | Spectral + NN | Spectral + NN (เหมือนกัน) |
| Hardware | ESP32-S3 DevKit | ESP32-S3 ติดกล่อง IP67 |
| Output | Serial monitor | MQTT alert to cloud |

**ข้อสรุปสำคัญ:** สิ่งที่ต่างกันคือ **domain และ dataset** — pipeline และ hardware เหมือนกันทุกอย่าง ทักษะที่เรียนในคอร์สนี้ transfer ไปงานจริงได้ทันที

## MPU-6050 ในโปรเจกต์ Edge Impulse + ESP32-S3

### สิ่งที่โปรเจกต์นี้ใช้จริง

โปรเจกต์ใช้เฉพาะ **Accelerometer 3 แกน** ที่ความถี่ 98 Hz ไม่ใช้ Gyroscope และไม่ใช้ DMP เพราะ Edge Impulse จัดการ DSP pipeline เองทั้งหมด

### การตั้งค่าที่ใช้ในโค้ด

```cpp
mpu.setAccelerometerRange(MPU6050_RANGE_4_G);
// ±4g = เหมาะกับ gesture มือ ไม่เกิน 4 เท่า gravity

mpu.setFilterBandwidth(MPU6050_BAND_44_HZ);
// Low-pass filter ตัดสัญญาณเหนือ 44 Hz
// เพราะ Nyquist theorem: sampling 98 Hz → เก็บได้สูงสุด 49 Hz
// 44 Hz < 49 Hz = ป้องกัน aliasing
```

### ทำไมใช้แค่ Accelerometer ไม่ใช้ Gyroscope

สำหรับ gesture ระดับนี้ (circle, up\_down, side\_side):

|  | Accelerometer | Gyroscope |
| --- | --- | --- |
| บอกทิศทาง | ✓ (gravity component) | ✗ |
| บอก pattern การเคลื่อนไหว | ✓ (FFT pattern ชัด) | ✓ แต่ซ้ำซ้อน |
| Noise | ปานกลาง | มี drift |
| Feature count | 3 | 3 (ถ้าเพิ่ม = 6) |
| ผลลัพธ์ | แยกได้ดี | ซับซ้อนขึ้นโดยไม่จำเป็น |

### ข้อจำกัดที่ควรรู้

1. **Orientation-dependent:** ถ้าจับ sensor กลับหัว ค่า gravity จะกลับทิศ — โมเดลอาจทายผิด ถ้าต้องการ orientation-invariant ต้องใช้ magnitude `|a| = √(x²+y²+z²)` หรือเพิ่ม Gyroscope
2. **Static vs Dynamic:** Accelerometer แยก static tilt (gravity) กับ dynamic acceleration ไม่ออกโดยตรง — FFT ช่วยแก้ปัญหานี้เพราะ static gravity เป็น DC component (0 Hz) ที่ FFT กรองแยกได้
3. **Vibration sensitivity:** ถ้าอยู่ใกล้มอเตอร์หรือเครื่องสั่น จะรบกวน signal — ใช้ `BAND_44_HZ` filter ช่วยได้บางส่วน
